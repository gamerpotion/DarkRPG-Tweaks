# Gradle build notes — DarkRPG Tweaks 1.0.0 Beta 2

This is a **Fabric Loom Gradle** source project for Minecraft 1.20.1.
The source uses **intermediary identifiers** (`class_1309`, etc.). To satisfy
Loom's requirement for a `named` development namespace, the build automatically
derives a valid **identity `intermediary` → `named` mapping** from published
Fabric Yarn 1.20.1 v2 mappings. This replaces the invalid attempt to feed Loom
the `net.fabricmc:intermediary` artifact directly. No Minecraft source is renamed.

## Requirements

- JDK 17 or 21 (compiles Java 17 bytecode)
- Gradle **8.8** installed (or an official Gradle wrapper generated locally)
- Internet access for the initial Minecraft, Fabric and optional-mod dependencies

## Build

```sh
gradle clean build
```

Gradle downloads Minecraft, the Yarn mapping artifact, Fabric Loader/API, and compile-only copies of
Origins 1.10.0, Amethyst Core 1.5.0 and Cosmetica 2.0.1 from public Maven
repositories. They are **not redistributed** with this source project.

The deployable Fabric mod JAR appears in `build/libs/`.
`gradle verifyBundledDatapacks` verifies the 144 TieredZ definitions and
the 24 Soulslike spell assignments, including Beta 2 rarity weights.

## Standard wrapper (optional)

An official `gradle-wrapper.jar` cannot be generated by this source-only
distribution. With Gradle 8.8 installed, generate the official wrapper:

```sh
gradle wrapper --gradle-version 8.8 --distribution-type bin
./gradlew build
```

Commit all four official wrapper files if you want other contributors to
build with `./gradlew` instead of installing Gradle.

## Integration notes

- Install the compiled mod alongside the original required mods.
- No separate Paxi datapacks are needed: the built-in data overlays are
  enabled through Fabric API.
- The old HP-repair `/trigger darkunbug` function is intentionally absent.
- Runtime compatibility still requires in-game testing.

## CI

`.github/workflows/gradle.yml` builds using Gradle 8.8, JDK 17, and
uploads the compiled JAR as a GitHub Actions artifact.

### Loom dependency compatibility

The three optional mod API JARs (Origins 1.10.0, Amethyst Core 1.5.0,
Cosmetica 2.0.1) use Gradle `compileOnly` rather than Loom `modCompileOnly`.
This project deliberately uses Minecraft's *intermediary* names as its dev
mappings; the runtime Fabric mod JARs already reference these names. Sending
those JARs through Loom's remapper is unnecessary and can cause the
`Mod was built with a newer version of Loom` validation error in Loom 1.6.12.

This adjustment doesn't bundle optional mods into DarkRPG Tweaks or alter
the built-in datapack resources.

### Calio compile-only dependency

Origins 1.10.0 includes the Calio 1.11.0 library at runtime. The Origins
artifact downloaded from Modrinth does not expose nested dependencies to the
Java compiler, so referencing `OriginLayers.size()` also requires the Calio
`MultiJsonDataLoader` class on the compile classpath.

`build.gradle` adds the JitPack repository and a `compileOnly` dependency on
`com.github.apace100:calio:1.11.0`, with transitive dependencies disabled.
Calio is **not bundled** into the DarkRPG Tweaks output JAR, and no Java
compatibility code or datapack definitions are changed.
